# Pickaxe King Auto

自動化《Pickaxe King Island》（Android `com.rogueuniongames.pickaxekingisland`）的素材採集。
透過 adb 控制手機；**目前採用的做法是「錄下使用者的原始搖桿操作，再 1:1 重播」**。

## 為什麼是「重播操作」而不是「畫面辨識」

2026-10-19 試過各種「看畫面做決定」的路線（樹冠偵測、石頭偵測、白色瞄準框偵測、
目標導向走位、地圖建構、關鍵幀重播…）全部不穩定，原因：

- 樹被帳篷／建築／其他樹擋住 → **看得到才偵測**的做法永遠會漏。
- 但遊戲的規則是「**走過去就會自動揮砍**」→ 不需要知道樹在哪，**走過生成範圍**就好。
- 所以：**固定路線 + 精準重播使用者操作**，路線內自然會撞到樹而被砍掉。

（唯一還需要辨識的是「傳送石」與「地區格子」，那兩個用範本比對很穩。）

## 現行流程

```
一次性：校正觸控座標（do_calib.py，需要使用者點四個十字）
每次：
  1. record_touch.py <路線名>      ← 使用者照平常走一次，程式只讀觸控事件
  2. 使用者走完後 touch data/touch/STOP（或等時間到）
  3. run_route.py <路線名> --area village|start
        ├─ teleport.go(area)  傳送到該地區落點（固定錨點）
        └─ replay_touch2.py   1:1 重播剛剛錄的觸控
```

### 指令

```bash
P=./.venv/Scripts/python.exe

# 校正（只需一次；會提示使用者點四個十字）
$P do_calib.py                 # 解出 data/touch/_calib.json

# 錄製路線（背景跑；使用者正常走動）
$P -u record_touch.py village_loop --seconds 1800
touch data/touch/STOP          # 走完後叫它收工（資料是邊錄邊存，不會丟）

# 重播
$P run_route.py village_loop --area village
$P replay_touch2.py village_loop --dry     # 只看會送什麼，不碰手機
```

## 這條路徑上踩過的坑（照順序記）

1. **移動是搖桿式**：角色在「手指按住」期間持續移動 → 移動量取決於**按住時間**，不是拖曳距離。
   （舊做法用拖曳長度控制 → 每次都少走 → 路線被壓縮。）
2. **觸控要錄核心事件**：`adb shell getevent -lt /dev/input/eventN` 可以讀到**使用者手指**的事件；
   但 `adb shell input tap`（電腦注入的）**不會**經過核心 → getevent 看不到，別拿它測試。
3. **裝置選擇**：三星有 `sec_touchpad`（保護蓋觸控板）也帶「touch」字樣，必須優先 `sec_touchscreen`。
4. **getevent 直接指定裝置時不印裝置名**：`[ ts ] EV_KEY BTN_TOUCH DOWN`（沒有 `/dev/input/eventX:` 前綴）。
5. **解析的坑**：值可能是 `DOWN`/`UP`（字串）或十六進位（`00000aa2`）。
   曾經用 `[0-9a-fA-F]+` 抓值 → `DOWN` 只抓到 `D` → 永遠配不到。
6. **DOWN 比座標先到**：一筆觸碰要拿「DOWN 之後第一次出現的 POSITION_X/Y」才是真正起點
   （DOWN 那行的座標是上一筆的殘值）。
7. **螢幕座標要實測校正**：raw(0–4095) 不是線性映射到 1440×3120（x、y 比例不同）→
   用「畫十字 + 使用者點」解出 `screen = a*raw + b`。實測誤差 0–70px，對搖桿足夠。
8. **重播要用 `input swipe`**：`input motionevent` 逐事件送＝每次都是一次獨立注入 →
   遊戲看成「一直點同一處」→ 角色原地打轉。swipe（按下→拖曳→放開一次完成）才對。
9. **一個手勢＝一次 swipe**：取「第一個 move 當起點、所有 move 的中位數當按住位置、原時間長度當 duration」。
10. **存檔要原子寫入**：`json.dump` 直接寫檔，程序被砍就留下半截 JSON；要寫 `.tmp` 再 `os.replace`。
11. **程序要殺乾淨**：Hermes 的 process kill 只殺外層，真正的 Python 子程序會活著 →
    多個殘留錄製器同時寫同一個檔 → 檔案一直變大且損毀。
    用 `Get-CimInstance Win32_Process` 依 CommandLine 找出全部再殺。

## 遊戲事實（使用者確認）

- 玩家角色**固定停在畫面 (720, 1400)**（水平置中、垂直中央偏上）。
- **走過去就會自動揮砍**；樹與石頭一下（1 hit）就砍掉，揮鎬約 0.2 秒一次。
- **樹＝深綠**（V 亮度較低）；**地板＝淺綠**（V 高）→ 這是唯一能分開兩者的可靠特徵。
- 樹／石頭在生成範圍內隨機長，砍掉後約 **100 秒**重生；樹石共用同一批生成位置。
- **可以穿越**：樹、石頭、NPC、人物、生物。**不能穿越**：建築物、河水、黃金樹。
- 小村莊有**黃金樹**（金黃色、會顯示提示文字）不能砍，而且會擋住其他樹與角色。
- 「白色四角框」＝**角色靠近可互動目標**時出現（樹、石頭、帳篷都有），不是「可砍」專屬。
- 砍伐時會跳**傷害數字**（曾固定 151，會變）；「木材 x N」掉落提示不可當判斷依據。
- 體力＝上方紅色條（數字/數字）；**降到 0 才回小屋休息**（休息約 3 秒，生命值不為 0 時不要按）。
- 傳送石＝右側**藍色愛心**（有冷卻，會顯示「2s」），點開是可捲動的地區選單
  （關閉＝點面板外空白處）。

## 結構

```
pkauto/adb.py        adb 控制層（截圖／點擊／swipe／按鍵）
pkauto/vision.py     影像工具（世界位移、模板比對、亮度正規化）
pkauto/hp.py         生命值數字辨識
pkauto/teleport.py   傳送石流程（愛心範本 + 選單格子靜止確認）
record_touch.py      錄製原始觸控（getevent → data/touch/<name>.json）
replay_touch2.py     1:1 重播（swipe 手勢）
do_calib.py          觸控座標校正（→ data/touch/_calib.json）
calib_listen.py      校正用：監聽真實觸控取樣本
run_route.py         傳送 + 重播一條路線
pk.py                CLI 入口（shot/tap/swipe/app/scroll）
tests/               合成影像單元測試（不需裝置）
captures/            執行時範本（tpl_*、hp_digits/；不進版控）
data/touch/          錄製的觸控與校正檔（進版控）
```
